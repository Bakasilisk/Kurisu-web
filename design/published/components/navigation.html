Two rows

The topbar is app-level and always present. The second row — .subnav, from _nav.html's guild_tabs macro — appears only when a page has a guild in context, and scopes to that one server. Splitting them is what lets the /guild/{id} (admin) and /me/{id} (member) route trees read as one place: before the tab bar, those were two unconnected sets of URLs a user had to already know about.

Tabs

Underline tabs, not pills. The marker is a 2px ::after filled with --brand-grad, scaled to 0 by default and to 1 on the current tab — so it matches the h2 rule and the brand mark rather than being a flat border. Because it is a transform on an always-present element, nothing shifts by 2px when the active tab changes, and hovering a tab previews it at 60% width. The active tab is marked with aria-current="page" — that attribute is the styling hook as well as the semantics, so the two can't drift apart.

The macro is handed can_admin / can_member and only decides what to show — every route still runs its own authorization. A member without admin rights sees two tabs here, not five. It performs no access checks of its own; hiding a tab is never the control.

Switcher

A bare <details> dropdown, rendered only when there's more than one guild to switch between — so the common single-server case gets no dead control. No JavaScript: summary drops its native marker for a ::after caret, and the panel is absolutely positioned at z-index: 20, above the sticky topbar's 10. It's shown open here; it is closed by default.

The list caps at 60vh and scrolls — someone in forty servers gets a scroller, not a menu running off the viewport. Under 640px it anchors right: 0 instead of left, so a long server name expands inward rather than off-screen.

Behaviour

Sticky at top: 0 on z-index: 10, over --surface-1. The bottom edge is a gradient hairline drawn by ::after rather than a flat border-bottom — brand at the left, through --border, fading to nothing at the right. Where backdrop-filter is supported the background drops to 78% via color-mix and picks up a 14px blur at 1.6 saturation, so content reads through it as it scrolls under. The opaque surface is the fallback, declared first — nothing depends on the blur landing.

Structure

The wordmark takes margin-right: auto, which pushes everything after it to the right edge — so nav links, the current user and the logout link all sit in one right-hand cluster with no wrapper element. Links are --text-secondary at 500 and go to --brand on hover, with a gradient underline that wipes in from the left via a scaleX transform. The tab bar's active marker works the same way, so the two rows share one motion idea.

Theme toggle

A 32px icon button at the right end of the topbar, outside the {% if user %} block so the login page gets it too. Which glyph shows is decided in CSS from :root's state, not by JS swapping the button's contents — the moon shows while light is active (click to go dark) and the sun while dark is active. That keeps the two icons static markup and means the correct one is right on first paint.

The button only carries an icon, so it takes an aria-label, and aria-pressed tracks the dark state. Both are written by theme.js once it knows the active theme, which it resolves from data-theme when set and matchMedia otherwise.

The boot script has to be inline. A stored preference is applied by a small blocking <script> in base.html's <head>, before the stylesheet. Deferred or bottom-of-body, the page paints in the OS theme first and visibly flips — the one thing a theme toggle must never do. theme.js itself only wires the click, persists to localStorage, and dispatches a themechange event.

That event exists because Chart.js bakes its colours in at construction time. dashboard.js caches each box's last payload and re-renders from cache on themechange, so switching recolours the charts and the heatmap without a refetch or a loading flash. Anything else that reads a token at render time has to listen the same way.

Mark

The 9×18 pill left of the wordmark is a ::before on .brand filled with --brand-grad and lit by --shadow-brand. It gives the nav an anchor without needing an image asset, which keeps the app's no-external-requests policy intact — the only binary in static/vendor is the font and Chart.js.

Narrow

The two rows narrow differently, on purpose. Under 640px the topbar wraps: flex-wrap turns on, the gap tightens to --space-3, padding drops to match, and the link cluster falls to a second line under the wordmark.

The tab bar does the opposite — it stays one line and becomes a horizontal scroller. With five possible tabs, wrapping would push the page content down by an amount that depends on which tabs a given user can see, so the same page would start at a different offset for an admin and a member. A scroller keeps that fixed.
